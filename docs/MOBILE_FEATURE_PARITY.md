# デスクトップ版 → モバイル版 機能移植表

**作成: 2026-11-04 / 対象: デスクトップ v0.0.318、モバイル `apps/mobile`（M1 実装中）**

---

## 0. この文書の役割

`README.md` の「主な機能」は v0.0.261 の時点で書かれたまま 57 リリース分（v0.0.262〜318、165 コミット）置かれていた。
**この文書を作るにあたって README を v0.0.318 の実態に合わせて書き直した。** したがって:

- **デスクトップ版の機能の正典は `README.md#主な機能`。** こちらは「それをモバイルへどう運ぶか」だけを決める
- **モバイル版の設計の正典は [`MOBILE_FEASIBILITY_STUDY.md`](MOBILE_FEASIBILITY_STUDY.md)。** 画面仕様・不変条件・マイルストーンの定義はあちらにある
- この文書は**両者の対応表**であり、新しい決定はここでは行わない。表の中で「未決」と書いたものは §14 の未決番号を指す

### 更新のしかた（また 57 リリース溜めないために）

1. 新機能を含むリリースを出したら、`README.md#主な機能` に 1 行足す
2. 同時にこの表へ 1 行足し、**その時点での移植判断を書く**（「済」「M2」「見送り」のどれか）
3. モバイル側で実装したら、この表の状態を「済」に変える

デスクトップのリリースノートは `gh release view v0.0.NNN --json body -q .body` で遡れる。差分を数えるには `git log 1cb15e5..HEAD`（`1cb15e5` が README の前回更新）が起点になる。

## 1. 判定の凡例

| 記号 | 意味 |
|---|---|
| **済** | モバイル版に実装済み（M1 の範囲で動いている） |
| **M2** / **M3** / **M4** | 持っていく。実装するマイルストーン（§12。初版は M1〜M4 すべてを入れてから 1 本出す） |
| **形** | 概念を変換して持っていく。デスクトップと同じ形にはならない（§6-2） |
| **未決** | 持っていくかどうかが未決。§14 の番号を併記 |
| **×** | 持っていかない。理由を併記 |

**「形」は単独でも、他の記号と組み合わせても付く。** 「形 / 済」は変換した上で実装済み、「形 / M4」は変換して M4 で入れる、「形」単独は変換した結果デスクトップの項目が消える（対応するものが別の場所にある）。

### × になる理由は 5 つだけ

| 理由 | 説明 |
|---|---|
| **入力装置が無い** | マウスホバー / 右クリック / ホイール / キーボードショートカットに依存している。長押し・タップに変換できるものは「形」、できないものが × |
| **画面が無い** | 多ペイン・スプリッタ・別ウィンドウ・常に最前面など、ウィンドウを複数持てる前提の機能 |
| **OS が担う** | 自動アップデータ・ウィンドウ位置復元・シングルインスタンス。ストアと `expo-updates` が担当する |
| **不変条件に反する** | §2 の 5 条件に反するもの（広告・課金が該当） |
| **スコープ外（既決）** | デスクトップ版側で「着手しない」と決めてある項目。アクセシビリティ、類似スレ / 次スレ検索など（§12-5） |
