## デスクトップ版の仕組み（移植元）

1. ユーザーが例にするレス番号を入れる（例: `12 34 56`）。対象は本文か名前欄。
2. プロンプトは `NG_REGEX_GEN_INSTRUCTION` ＋「隠したい書き込みの本文の例:」＋ `例12: 本文…`（1 件 200 文字まで）。
3. アシスタントの答えの書き出しに **`答え: /`** を先に置き、続きだけを書かせる（`maxTokens: 64`）。
4. 1 行目を `/(.+)/[a-z]*` として読み、中身を取り出す。
5. **手元で実際に当てて確かめる。** 次の 3 つを満たした候補だけを見せる。
   - `checkNgRegex` を通ること。200 文字以内で、繰り返しの中に繰り返しが無く、`new RegExp(body, "im")` が通ること。
   - 例のレスの**すべて**に一致すること。
   - 例以外のレスへの一致が **30% 以下**であること（`NG_REGEX_GEN_MAX_RATE`）。
6. 候補は「このスレで x/y 件に一致」を付けて出し、押すと入力欄に入る。登録はユーザーが件数を見てから行う。

プロンプトの決め方の記録（Gemma 4 E2B で実測、App.tsx のコメントにもある）:
- 「1 行に 1 つ書く」と頼むと、例を 1 件ずつ書き写すだけになった。例のすべてに一致する候補は 0 件だった。
- 答えを 1 行に絞り、お手本を 2 つ見せる形に変えると、9 ケース中 8 ケースで使える候補が出た。お手本は「共通語を `|` で並べる」と「表記揺れを `( | )` で並べる」の 2 つ。
- 落ちた 1 件は顔文字（AA）のケース。全角と半角が混ざっていて、共通する語が作れなかった。

## 進め方（提案）

### 1. まずモデルごとの質を測る（実装より先）

デスクトップで測れたのは Gemma 4 E2B だけ。**4GB 端末向けの 1〜2B モデルで使える候補が出るかは分かっていない。**
Mac で llama.cpp を使い、モバイルのカタログにある各モデルで同じケースを回す。

- プロンプトは各モデルのチャットテンプレートで整形する。モバイルは `getFormattedChat` で整形するので、デスクトップの gemma4 固定テンプレートとは違う。
  - 例: `llama-server` の `/apply-template` で整形し、末尾に `答え: /` を付けて `/completion` に送る。
  - `temperature: 0.3`、`n_predict: 64`、thinking は切る。
- 判定はデスクトップの手順 5 と同じにする。普通のレス約 40 件の中に例を散らして置き、「例に全部一致」かつ「例以外 30% 以下」なら合格。
- ケース（デスクトップの検証で使ったもの。例 2〜3 件ずつ）:

| ケース | 対象 | 例 |
|---|---|---|
| 副業宣伝 | 本文 | `在宅で月収30万円！スマホだけでOK 詳しくは→ https://bit.ly/3xAbC12` / `【簡単副業】スマホで月50万稼げる方法 https://bit.ly/9ZzQ0k 今だけ無料` / `主婦でも月収20万！在宅ワークの詳細はこちら https://bit.ly/4Kp77a` |
| キモオタ表記揺れ | 本文 | `ここはキモオタの巣窟ですねｗｗｗ` / `ｷﾓｵﾀ乙ｗｗｗ 巣に帰れ` / `きもおた必死すぎて草www` |
| はい論破 | 本文 | `はい論破。お前の負け` / `はい論破ｗ 反論できないの？` / `はいはい論破論破` |
| まとめURL | 本文 | `【速報】芸能人の流出画像まとめ ttps://matome-news.xyz/123` / `流出画像まとめはこちら ttps://matome-news.xyz/456` |

- 普通のレスには、例と同じ語を少し含むものを混ぜておく。例: 「論破って言葉を使う人はちょっと苦手」「月収の話はやめとけ荒れる」「キモいとか言うなよ」「転売は法律で規制すべき」。

### 2. 決めること（ユーザーに確認する）

- **使えるモデル**: 1. の結果を見て決める。全部の生成モデルで出すか、使える候補が出たモデル（たとえば Gemma 4 E2B / Qwen3.5 4B）を選んでいるときだけにするか。
- **入口**: 案は 2 つ。
  - 既存の `AiRuleSuggestSheet` に「正規表現で作る」を足し、曖昧 NG と切り替える。
  - レスメニューに「AI: このレスから正規表現 NG を作る」を別の項目として足す。
- **対象**: 本文だけにするか、名前欄も選べるようにするか（デスクトップは両方）。

### 3. 実装の目安

- `src/ai/` に正規表現版のモジュールを足す（例: `regexSuggest.js`）。中身はプロンプト、答えの解析、`checkNgRegex` 相当の確認、当たり具合の計算。純粋な関数にして `__tests__/lib` か `__tests__/ai` でテストする。
- 確認は `ngMatch` と同じ `'im'` で、スレの全レスに当てる。軽いので、曖昧 NG のように判定器を載せ替える必要はない（`NG_MODEL_ID` は要らない）。
- 例以外のレスの数え方: `rows` に渡している `shown` は、もう NG で隠れたレスを含まない可能性がある。分母に何を使うかはコードを見て決める。デスクトップは表示中のスレの全レスを使っている。
- 候補は件数（「例 3/3・このスレで 5/120 件」）を付けて出し、直してから追加できるようにする。直した候補はその場で数え直してよい（正規表現は軽いので、曖昧 NG と違って「直した文は測っていません」にしなくてよい）。
- 追加は `addNg({ list, value: '/…/' })`。
- 弾いた候補しか無いときは、デスクトップと同じように理由を出す。文言は「AIの答え /…/ は、例のすべてに一致しないか広すぎるので出していません。例を変えて試してください」。

### 4. 確かめること

- `npx jest` / `npx eslint src __tests__`
- iOS シミュレーターか実機で、レスメニューから開いて候補が出て追加できるところまで。
  - idb はタップを送れないので、操作はユーザーに頼み、画面は `xcrun simctl io booted screenshot` で見る（`HANDOFF_MAC_MOBILE_NOTIFY.md` と同じ運用）。

## 守ること

- `.catch(() => {})` 禁止（`console.warn` で残す）。新しい依存は足さない。
- 生成中はアプリが裏に回ると止まる（`watchAppStateForAi`）。長い処理は `isStopRequested()` を見て抜ける。
- モバイルのリリース（EAS）は確認が済んでから別に判断する。
